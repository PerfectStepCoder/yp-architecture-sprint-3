### **4. Проблемы монолитного решения**

Основные недостатки текущего решения (монолита):
- используется одна БД для хранения состояния всех датчиков всех пользователей, при большой количестве пользователей это будет узким местом, много операций чтения и записи
- запросы на установку температуры для датчиков синхронные, при сбои сервиса мы не сохраним новое значение температуры, которую выставляет пользователь
- в целом система не маштабируется, например можно увеличить количество инстансов сайта и бека, но БД общая которая не даст нужный прирост производительности

### 1. Тип API

Укажите, какой тип API вы будете использовать для взаимодействия микросервисов. Объясните своё решение.

Между микросервисами я использую преимущественно синхронное взаимодествия, в случае когда я запрашиваю текущий статус Умных модулей (датчиков), в случае передачи команды на выполнение Умными Модулями я использую асинхронное взаимодействие (потому что выполнение команд не всегда возможно выполнить мнгновенно, например для датчика открытия ворот).
